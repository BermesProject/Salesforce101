# 아이웨어 고객 상담 실습

젠틀몬스터를 참고한 가상 매장 **마일드몬스터**입니다. 앤디가 받은 상담 중 도움 요청 또는 첫 응답 지연 건을 미란다가 이어받습니다. 나이젤은 고객 별칭으로 저장합니다.

## 기본 환경

`schema.json`에 따라 `Luxury_Client_Consultation__c`와 18개 필드를 준비해 주세요. Name은 AutoNumber `LCC-{0000}`입니다. 앱 API는 `Luxury_Client_Consultation_Operations`, 표시 이름은 `마일드몬스터 고객 상담`, Permission Set은 `Luxury_Client_Consultation_User`입니다.

화면에는 고객·요청, 상태·시각, 담당 직원·도움 요청, 자동화 결과 네 묶음을 배치해 주세요. 현재 처리 직원과 에스컬레이션 상태·사유·시각은 화면 읽기 전용입니다. 기존 `Next_Contact_Date__c`와 연락 동의 등 필드는 삭제하지 말아 주세요.

담당 직원과 상위 직원 Lookup은 활성 직원만 선택할 수 있도록 필터를 구성해 주세요. 앤디 `EMP-LUX-001`, 미란다 `EMP-LUX-002`로 연결하고 서로 같은 직원이 되지 않도록 확인해 주세요.

## 시간과 데이터 준비

1. 교육생 계정의 시간대와 화면 시간을 확인해 주세요. 수업 기준은 Asia/Seoul입니다. 계정 설정 변경이 필요하면 먼저 안내해 주세요.
2. 같은 상담 결과 필드를 갱신하는 활성 자동화가 있는지 확인해 주세요. 초기 등록은 이번 수업 Flow가 비활성인 상태에서 진행합니다.
3. 현재 시각의 시간대 오프셋을 포함한 값을 한 번만 정하여 다음 스크립트에 전달해 주세요. 아래는 형식 예시이므로 실행 당시 시각으로 바꾸어 주세요.

```sh
python3 Day2/scripts/prepare_eyewear.py \
  --anchor 2026-10-13T10:00:00+09:00 \
  --output /tmp/salesforce101-day2-eyewear.json
```

저장소 루트에서 실행하는 명령입니다. 스크립트는 org에 접속하지 않고 오프셋을 날짜/시각으로 바꿉니다. 출력에는 같은 t0와 10건이 들어갑니다. 출력 파일은 재실행으로 덮어쓰지 않습니다. 실제 ID로 Lookup을 연결하는 과정은 별도로 필요합니다.

4. A/B/C 3건을 먼저 생성하고 기한·등급·직원을 확인해 주세요. 나머지 `GM-BASE-01~07`은 같은 파일에서 추가해 주세요. 기존 레코드가 있으면 t0를 새로 계산하여 덮어쓰지 말아 주세요.
5. `GM-ESC-D/E`는 장표에서 직접 만들기 때문에 기본 등록에서 제외해 주세요.

## 수업에서 추가할 규칙과 Flow

기본 데이터를 확인한 다음 아래 규칙을 구현해 주세요. 기존 레코드가 있다면 적용 범위를 먼저 검토해 주세요.

- 고객 별칭·등급·요청 내용·상담 상태·접수·기한·담당 직원·상위 직원은 필수 입력입니다. 메타데이터 수준 Required로 일괄 변경하기보다 해당 실습의 Validation Rule과 화면 입력 조건을 검토해 주세요.
- 기한은 접수보다 빠를 수 없습니다. 첫 응답은 접수 이후이며 미래일 수 없습니다.
- 매니저 도움 필요가 true이면 도움 요청 사유가 필요합니다. 담당 직원과 상위 직원이 같을 수 없습니다.
- `Before-save Record-Triggered Flow`를 생성해 주세요. 같은 레코드의 결과 필드는 Assignment로 변경하며 별도 Update Records를 두지 않습니다.

분기는 다음 순서를 지켜 주세요.

1. 상담 완료이면 기존 에스컬레이션 요청을 처리완료로 바꾸어 주세요. 미요청으로 완료한 건은 미요청과 앤디를 유지합니다. 이미 이관된 건의 담당·사유·최초 시각은 보존합니다.
2. 미완료이고 이미 요청/처리완료 이력이 있으면 결과를 보존해 주세요. 이번 실습에서 재개방·재이관은 다루지 않습니다.
3. 미이관이고 `Needs_Manager=true` 또는 `(기한 있음 AND 첫 응답 공란 AND 기한<현재 시각)`이면 상위 직원과 필요한 사유를 검증한 뒤 이관합니다.
4. 이관 시 현재 직원=상위 직원, 상태=요청, 사유=직접 도움 사유 또는 `첫 응답 기한 초과`, 시각=최초 이관 시각으로 설정해 주세요.
5. 조건이 없으면 현재 직원=담당 직원, 상태=미요청, 사유·시각=공란으로 설정해 주세요.

활성화 후 A/B/C를 다시 저장해 주세요. B/C가 미란다에게 보이는지 확인하고, B를 완료하면 처리완료가 되는지 확인해 주세요. 반복 저장해도 최초 이관 시각은 바뀌지 않아야 합니다. 시간 경과만으로 실행되는 자동화는 포함하지 않습니다. 예약 경로는 확장 주제로 남깁니다.

미란다 목록은 모든 레코드 범위에서 `Escalation_Status=요청 AND Consultation_Status!=완료 AND Current_Handler=미란다의 실제 Employee ID`로 구성해 주세요. Owner/User 기준 필터나 Employee 대상 실제 알림 발송은 사용하지 않습니다.
